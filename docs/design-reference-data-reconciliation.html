3aData Reconciliation Monitor - "Control Room"

Design reference - Thornfield Retail Group

Five page archetypes for a source-vs-warehouse reconciliation and data quality monitor. Fictional client: Thornfield Retail Group, a multi-channel retailer whose data platform team runs this report as the morning check before the business opens its dashboards: did last night's loads land, do the warehouse numbers match the source systems, and which breaks need chasing. The audience is engineers and analysts, so the set goes dark - the visual language of observability tooling, kept quiet. Canvas is 1280x720 (Power BI default). Numbers on these mockups are illustrative placeholders; in the built report every figure traces to the committed data generator. Numbered dots map to the notes beside each page.

Design system at a glance

Palette - status is a traffic discipline, everything else stays quiet
#14181FPage canvas - deep slate, never pure black
#1C222BVisual cards, 6px radius, hairline border
#58B7D4Cyan = data flow: row volumes, trends, titles
#57A773Green = check passed, nothing else
#D9A03FAmber = warning: inside tolerance but drifting, or late
#D65F5FRed = failed check or open break, nothing else
#E6EBF2Ink - headings and body on dark
#8A96A6Secondary text, axis labels, context lines
Type - Segoe UI (Power BI native), tabular figures throughout
Report title 20px semibold
99.97% KPI number 28-30px bold
Visual title 11px caps 700 cyan
Axis / table body 10-11px, tabular numerals, secondary #8A96A6
Signature rules
  • Pass / warn / fail is the only colour story. Green means a check passed, red means it failed or a break is open, amber means inside tolerance but worth a look. No other meaning ever borrows these colours.
  • The check grid (feed by day, one square per nightly run) is the recurring signature move - a CI pipeline read: scan a fortnight of history in one glance.
  • Zero means zero. Variances are shown exactly, signed, with thousands separators; a matched feed shows 0, not blank. Every count is pairwise: source next to warehouse.
  • 24px margins, 8px grid. Fixed bands: title + slicers, KPI band (~104px), then content rows. Money and counts right-aligned, tabular numerals.

Reconciliation - the pairwise proof

1Every count is pairwise: source rows next to warehouse rows, source amount next to warehouse amount, then the signed delta. A matched feed shows 0, not blank - zero means zero. Master-data feeds without a monetary measure show a dash, honestly.
2Status is judged against a stated tolerance (in the card header, not hidden in a tooltip): row counts exact, amounts within ±0.05%. E-commerce is inside tolerance, so amber not red.
3The check grid, the signature move: one square per feed per night, a fortnight deep. Recurring amber on one feed reads as a pattern, not an incident. Right-click a row to drill through to the feed detail page.

Feed detail - the drillthrough target

1Back button (auto-added by drillthrough) replaces the logo - this page is a destination, not a nav stop. One detail page serves all eight feeds.
2Header card holds the whole feed in one band: source system, last verdict, pairwise rows, amount delta, and the named data steward. The left edge takes the status colour.
3Paired columns, source beside warehouse, a fortnight deep. The warehouse bar turns red only on the nights it failed to match; the 21st shows near-zero volume because no files were due (Sunday), which the checks treat as no-run, not failure.
4The feed's open breaks travel with it, same columns as the register, so the drill ends at the action list.
